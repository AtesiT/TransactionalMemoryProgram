# Transactional Memory — MAUI STM Lab

Учебное кроссплатформенное приложение на .NET MAUI, посвящённое транзакционной памяти. В интерфейсе можно переводить средства между двумя счетами, запускать параллельную нагрузку и наблюдать версии ячеек, конфликты и повторы.

## Что реализовано

- **STM-ядро** в `src/TransactionalMemory.Core`: локальные наборы чтения/записи, проверка версий, атомарная фиксация нескольких ячеек, повтор транзакции при конфликте и ограничение числа попыток.
- **Банковский пример**: перевод между двумя счетами — обе записи фиксируются вместе или не фиксируются вовсе. Отказ из-за недостатка средств не меняет ни один баланс.
- **MAUI-интерфейс**: одиночные переводы, параллельный тест (2–250 запросов), счётчики попыток/конфликтов, версии данных, журнал событий, сброс состояния и краткое сравнение `lock` с STM.
- **Проверки без внешних test-пакетов** в `tests/TransactionalMemory.Core.Specs`: корректный перевод, отказ без частичных изменений, параллельное сохранение общей суммы и повтор после контролируемого конфликта.

## Запуск

Требуется .NET 8 SDK. Для MAUI установите соответствующий workload и платформенные инструменты:

```bash
dotnet workload install maui
```

Затем откройте `TransactionalMemoryProgram.sln` в Visual Studio с компонентом .NET MAUI либо запустите проект с подходящей целью платформы, например Android:

```bash
dotnet build src/TransactionalMemory.Maui/TransactionalMemory.Maui.csproj -f net8.0-android
dotnet build tests/TransactionalMemory.Core.Specs/TransactionalMemory.Core.Specs.csproj
dotnet run --project tests/TransactionalMemory.Core.Specs/TransactionalMemory.Core.Specs.csproj
```

Для Android нужен Android SDK/эмулятор; сборка iOS и Mac Catalyst требует macOS и Xcode. В Visual Studio на Windows доступна также цель `net8.0-windows10.0.19041.0`.

## Модель транзакции

1. Поток читает версии ячеек и держит свои записи локально.
2. На commit движок проверяет, что все прочитанные версии не изменились.
3. Если версия устарела, локальный набор отбрасывается и тело запускается снова. Если проверки прошли, все записи публикуются в одной короткой критической секции.

Это упрощённая **учебная** STM: для атомарной фиксации внутри движка используется короткая блокировка, поэтому реализация не является lock-free и не обещает превосходства над `lock`. Значения ячеек следует считать неизменяемыми; тело транзакции может быть вызвано повторно и не должно выполнять ввод-вывод или другие внешние побочные эффекты.

Приложенный PDF содержит обзор истории STM и концептуальный пример для .NET. Реализация в этом проекте намеренно использует полноценный журнал и проверку версий вместо простого свойства `Value`, которое изменяло бы общую память сразу и не могло бы обеспечить настоящий откат.
